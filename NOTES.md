# Проблемы и возможные улучшения

## Проблемы, возникшие в процессе разработки

### 1. Неверные правила для фамилии в `$rules`
Изначально в `data/arrays.php` раздел `surname` содержал окончания `ич` и `вна`, которые относятся к отчеству. Из-за этого `getGenderDescription` показывала `Женщины - 0%` — все женщины уходили в `unknown`, так как функция не получала `-1` по фамилии.

**Решение:** исправить окончания на `в` (мужской) и `ва` (женский).

### 2. `getGenderFromName` возвращала сырое значение вместо нормализованного
Функция возвращала `$sexChar` напрямую (мог быть `2`, `-3` и т.д.), хотя по заданию должна возвращать только `1`, `-1` или `0`. Из-за этого условие `$gender === -1` в `getGenderDescription` не срабатывало для людей с несколькими женскими признаками.

**Решение:** добавить нормализацию в конец функции:
```php
if ($sexChar > 0) return 1;
if ($sexChar < 0) return -1;
return 0;
```

### 3. Неверное имя переменной в `index.php`
В вызове `getPerfectPartner` передавалась переменная `$persons`, которая не объявлена — вместо неё в `arrays.php` используется `$examplePersonsArray`. Это приводило к `Fatal error: Argument must be of type array, null given`.

**Решение:** заменить `$persons` на `$examplePersonsArray`.

### 4. `getPerfectPartner` не приводила регистр входных данных
Задание требует поддержки любого регистра (`ИВАНОВ ИВАН ИВАНОВИЧ`, `иВаНоВ иВаН иВаНоВиЧ`). Без нормализации `getGenderFromName` могла не распознать окончания в верхнем регистре, так как сравнение строк регистрозависимое.

**Решение:** обернуть каждый аргумент в `getFirstCharUpper` перед передачей в `getFullnameFromParts`.

## Возможные улучшения

### 1. Бесконечный цикл в `getPerfectPartner`
`while (true)` без выхода по условию опасен. Если в массиве нет людей противоположного пола (например, все `unknown`) — функция зависнет навсегда.

**Улучшение:** добавить счётчик попыток или предварительно отфильтровать кандидатов:
```php
$candidates = array_filter($persons, fn($p) => getGenderFromName($p['fullname'], $rules) * $gender < 0);
if (empty($candidates)) return 'Подходящий партнёр не найден';
$partner = $candidates[array_rand($candidates)];
```

### 2. Правила определения пола слишком грубые
Окончание `а` у имени даёт женский признак, но имена типа `Муса`, `Лука`, `Никита` — мужские. Аналогично `н` — мужской признак, но `Мариан`, `Жаклин` — женские. Это приводит к неверному определению пола для нестандартных имён.

**Улучшение:** расширить набор правил или добавить словарь исключений.

### 3. `getGenderDescription` вызывает `getGenderFromName` трижды для каждого человека
Три `array_filter` с одинаковым вызовом `getGenderFromName` означают тройной проход по массиву и тройной расчёт для каждого человека.

**Улучшение:** сделать один проход и группировать результаты:
```php
$counts = ['male' => 0, 'female' => 0, 'unknown' => 0];
foreach ($persons as $person) {
    $g = getGenderFromName($person['fullname'], $rules);
    if ($g === 1) $counts['male']++;
    elseif ($g === -1) $counts['female']++;
    else $counts['unknown']++;
}
```

### 4. Нет валидации входных данных
`getPartsFromFullname` использует `array_combine` с фиксированным массивом из 3 ключей. Если передать строку с двумя или четырьмя словами — `array_combine` вернёт `false` или выбросит ошибку.

**Улучшение:** добавить проверку количества частей перед `array_combine`.

### 5. Отсутствуют unit-тесты
Логика `getGenderFromName` нетривиальна и чувствительна к структуре `$rules`. Без тестов сложно убедиться в корректности при изменении правил.

**Улучшение:** добавить тесты через PHPUnit с набором известных имён и ожидаемых результатов.
